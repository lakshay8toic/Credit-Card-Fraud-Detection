# Live Demo

A small web app that runs the trained fraud detection models on real
transactions, one at a time, so the project can be demonstrated rather than
only described.

## Setup (do this once)

**1. Install the packages**

```bash
pip install -r requirements.txt
pip install -r Demo/requirements.txt
```

**2. Put the dataset in place**

Download `creditcard.csv` from
<https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud> and save it as
`Dataset/creditcard.csv`.

**3. Train and export the demo models**

```bash
python Demo/build_demo.py
```

This takes about a minute. It trains a Decision Tree, a Random Forest and an
XGBoost model on the same split used by the notebooks (random seed 77), saves
them into `Demo/models/`, and writes a small sample of the test set into
`Demo/data/` so the app does not need the full 144 MB file.

## Running the demo

```bash
streamlit run Demo/app.py
```

The app opens in a browser at <http://localhost:8501>.

## What the app shows

**Tab 1 — Check a transaction.** Shows one real transaction and the model's
verdict, with the probability it assigned. Buttons let you jump to a real
fraud or a legitimate transaction. After the verdict it reveals whether the
model was right, and labels the outcome as a true positive, false positive or
false negative. For the Decision Tree it prints the exact chain of yes/no
questions the model followed, so the decision can be read off the screen.

**Tab 2 — Run on many transactions.** Scores the whole demo sample at once and
shows the confusion matrix, how many frauds were caught and missed, and how
many false alarms an analyst team would have to work through.

**Tab 3 — Why we do not report accuracy.** Compares the trained models against
a "model" that always answers legitimate, which scores over 99.8% accuracy
while catching nothing.

The threshold slider in the sidebar changes the point at which a transaction is
flagged. Moving it live is the clearest way to show the trade-off between
catching fraud and raising false alarms.

## Notes

- `Demo/models/` and `Demo/data/` are generated by `build_demo.py` and are not
  committed to the repository.
- No model is trained inside the app. Training happens once, in
  `build_demo.py`, so the demo starts instantly.
- The app uses exactly the same data cleaning and train/test split as the
  notebooks, by importing `Code/utils.py`.
